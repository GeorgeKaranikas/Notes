# Prompt1 - web security course

Act as an expert cybersecurity curriculum developer and instructional designer where you have also experience as an expert Principal Application Security Auditor.Your task is to build a modern,  expert level curricullum course for students to reach the level world class web pentester/application security practitioner.

The course topic is Web Security Vulnerabilities and its curricullum follows famous courses and classes of the industry like TCM's web pentesting certifications and courses, the Burpsuite web academy`s curricullum topics as well as owasp top 10,cwe top 25,etc. .Its focused in white-box pentesting/security auditing/secure coding perspective mostly, but recomendetion on black box approach should be included as well.
The black box prespective is important as part of the pentesting methodology , so make sure to not just include a bash command or hacking tool, but provide detailed information on how to approach the discovery and testing process of the vulnerability.Chain the theory of known pentesting methodologies for every module with its theory which is presented by coding paradigms where the vulnerability is showcased. 
The course should take more than 6 months to complete with deep researching and paying attention to the details. This is a genuinely large undertaking — close to writing a multi-thousand-page reference text.

Besides, single well defined vulnerability families, the course will include bad practises (like programming laguage specific gotchas, normalization after sanitization etc.etc.) that are not consider as vulnerabilities themselves,  but become dangerous if combined with other bad practises and leave the codebase vulnerable. These would be paradigms seen in bigger projects and known to be vulnerable if combined.

For every single vulnerability family(or bad practise or whatever you choose as a chapter) you are going to divide to 3 or 4 levels(maybe more if you find this necessary) of difficulty and for each one of them  you will present :
- vulnerable snippets of code (maybe extensive paradigms with some of the rest of the code the app may provide, to build the relevant context). 
For every level of dificulty you should include snippets for 3 or 4 of the most used languages/frameworks for this specific application where the vulnerabilty is likely to show up, from the following languages pool: Python,Nodejs,Java,Ruby,Rust,Golang,c#.
- Accompanied with nginx or varnish web server config files as a front end server in levels of higher difficulty.
- Exploit paths and attacking exploits when refering to pentesting methodologies and black box testing.
- Remediation .Your expertise in web security will be particularly valuable in 
ensuring that any code developed meets the highest security standards. You should provide guidance on secure coding practices. This may include identifying common coding mistakes that could lead to vulnerabilities, suggesting ways to improve the code's overall security, and recommending tools or techniques that can be used to detect and prevent potential threats, if any. 

Each module should be delivered as a whole, dont split it in chat and files , as it needs to be exported for further reading.

Provide deep dive knowledge and make sure you teach comprehensive details so the learner avoids to miss possible exploitable code in the future.
You should start from fundementals for every vulnerability but as you procede with levels you are free to combine bad coding practises and previously seen exploiting paths by the community( bug reports, known attacks,ctfs etc.) , to build more context and provide more knowledge.
